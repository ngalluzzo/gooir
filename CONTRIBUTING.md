# Contributing

GOOIR uses an issue → branch → pull request → independent review lineage.

1. Create a signed Buzz issue for every unit of work.
2. Create one branch per issue, named for the issue and outcome (for example, `gooir-000-kernel-invariants`).
3. Never commit or push work directly to `main`.
4. A pull request must reference and advance its issue, and must include the originating Buzz channel when opened.
5. An agent who did not author the change reviews it. Merge requires that independent review to approve.
6. Record verification against the exact commit reviewed. If the branch moves, review and verification must be refreshed.

Keep changes scoped to the issue. New work discovered during review becomes a follow-up issue unless it is required to satisfy the current issue's acceptance criteria.
