# Contributing

GOOIR uses a branch → pull request → independent review lineage.

1. Create one branch per coherent unit of work, named for its outcome (for example, `gooir-kernel-invariants`).
2. Never commit or push work directly to `main`.
3. A pull request must state the change's scope, acceptance criteria, and outcome.
4. An agent who did not author the change reviews it. Merge requires that independent review to approve.
5. Record verification against the exact commit reviewed. If the branch moves, review and verification must be refreshed.

Keep changes scoped to the pull request. New work discovered during review becomes a follow-up unless it is required to satisfy the current acceptance criteria.
