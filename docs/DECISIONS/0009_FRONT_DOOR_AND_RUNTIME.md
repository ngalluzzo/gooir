# 0009 — A front door, and something that runs

Status: complete — the ship gate is now testable

## The gap this closes

Everything built before this required software that already exists. Every entry
point into the waist was a lifter over a Prisma schema or a live catalog, and
the target user — someone about to build an application — has neither. There was
no front door, and nothing that ran.

Two pieces, deliberately not a third target or more verification.

## The front door: `entity-spec`

A hand-writable surface that names exactly what the waist carries and nothing
more, so it cannot drift into a second vocabulary.

```text
entity Task
  id          uuid       pk = uuid
  title       text
  notes       text?
  status      enum TaskStatus(todo, doing, blocked, done) = todo
  priority    integer    = 3
  assigneeId  -> Person
  teamId      -> Team
  createdAt   timestamp  = now
  unique(title, teamId)
```

`->` takes its column type from the target's `pk`, so a foreign key cannot drift
from the key it references. A relation to a keyless entity is refused
(`SubjectUnresolvable`) rather than guessed.

The format round-trips through itself, and `examples/tasks.entities` is verified
through the **existing** store round trip — the front door inherits the whole
verification stack rather than getting its own:

```
examples/tasks.entities   ent 3->3  field_div=0  attr_div=0/107
                          unique_set_div=0  rel 3->3  rel_div=0
```

### A waist change the front door forced

`= todo` was accepted and then thrown away: the waist recorded only that a
default *existed*, so the DDL lowering emitted `members[0]` and happened to be
right by luck. For an authoring surface that is simply wrong output.

`FieldShape::default_value` now carries the literal. Following the enum-order
precedent from [0008](0008_POLYMORPHIC_CRUD_SURFACE.md), it is **kept but not
compared across authorities** — expression formatting is authority-local, a
store rewrites `now()` and re-qualifies casts. It is verified behaviourally
instead, which is stronger: after applying the generated DDL, the database
carries exactly what was authored.

```
Task.status = 'todo'::"TaskStatus"     Task.priority = 3
Person.createdAt = now()              Team.createdAt = now()
```

## The runnable target: `app-runtime`

One binary. Point it at a `.entities` file and it applies the schema, then
serves a validated REST surface.

```bash
cargo run -p app-runtime -- examples/tasks.entities --port 8080 --reset
```

**Nothing in the runtime knows what a Task is.** Routes, request validation, SQL
and defaults are all read off the model per request:

- which fields exist, which are required, which domain each admits;
- enumeration membership;
- that the identity is immutable;
- that a server-supplied field is not demanded of the caller;
- application-origin defaults, generated by the runtime because the store will
  not supply them (delegated to `gen_random_uuid()` rather than reimplemented).

This is the "80% is generic over the entity" claim from
[0004](0004_RECURRENCE_PROBE.md) made executable rather than asserted: one
implementation, any model.

PostgreSQL is reached through `psql`. That keeps the authoritative client
authoritative and this workspace free of a driver stack, and it is honestly a
milestone choice — a real deployment wants a pooled client.

## Verified end to end

`scripts/app-runtime-smoke.sh` — 28 checks, all passing:

| group | checks |
| --- | --- |
| serving | discovery, OpenAPI document, empty collection |
| creation | team, person, task; both authored defaults land |
| validation from the model | unknown field, enum non-member, wrong scalar, missing required, null on required, immutable identity, malformed path id, invalid JSON |
| store-enforced | duplicate unique → 409, delete a referenced row → 409 |
| lifecycle | read, update, persisted, 404s, 405, delete, gone |

## Two defects the runtime exposed

**Path parameters were never validated.** Bodies were checked against the waist
from the start; the identity in the URL was not. A malformed id produced `500`
with raw SQL in the response body. The waist already knew the identity field's
domain — the code just did not ask it. Now `400` with a clean message, and store
errors are mapped by class rather than dumped.

**The harness was mangling its own requests.** Three `POST /Person` calls
arrived carrying `"email":"..."`, `"name":"Ada"` and `"teamId":"..."` as
separate bodies — the braces gone, split on commas. Bash **brace expansion**,
firing on a JSON literal written inside nested command substitution. The runtime
had been correct the whole time.

That was only visible because the harness prints response bodies on failure.
The first version reported nine failures and no cause, and the temptation was to
debug the server. **A test harness is code, and an unverified harness produces
false findings in both directions.** Bodies are now built in variables, which
cannot be brace-expanded.

## Where the ship gate stands

> Someone goes from describing their entities to a running app with CRUD in
> under 30 minutes.

Testable for the first time, and currently met for the CRUD half: a text file
becomes a validated API in one command. **Admin views and auth wiring are still
absent**, so the gate as written is not yet satisfied — but it is no longer
unmeasurable, which is what every previous attempt lacked.
